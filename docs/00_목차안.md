## 1. 교재의 기본 방향

이 교재는 강사가 앞에서 설명하고 끝나는 강의안이 아니라, 직원이 혼자 보고 따라가며 작은 프로젝트를 끝낼 수 있는 자율학습형 워크북이다.

핵심 메시지는 다음과 같다.

> AI를 잘 쓴다는 것은 완성된 프롬프트를 외우는 것이 아니라,  
> AI와 대화하면서 업무 맥락, 조건, 판단 기준을 함께 만들고,  
> 한 번 해낸 일을 다음에도 재현할 수 있게 절차로 남기는 것이다.

따라서 `Skill 만들기`는 출발점이 아니다. 먼저 실제 문제를 풀고, 시행착오를 겪고, 검수 기준을 세운 뒤, 마지막에 그 절차를 `SKILL.md`로 남긴다.

처음에는 Codex Desktop으로 시작한다. CLI, MCP, Playwright 같은 말은 필요한 순간에만 등장시킨다. 직원이 먼저 익혀야 할 것은 도구 이름이 아니라, 공개 가능한 자료를 주고, 작업을 맡기고, 결과를 확인하고, 다음에 반복할 수 있게 남기는 흐름이다.

## 2. 프롬프트를 다루는 방식

이 교재는 "좋은 프롬프트 모음집"이 아니다. 직원에게 긴 문장을 완성해서 넣어야 AI가 일을 잘한다고 가르치면 안 된다.

이 교재에서 프롬프트 예시는 정답 문장이 아니라 대화 시작문이다. 사용자는 처음부터 모든 조건을 완벽하게 쓰지 않아도 된다. 오히려 Codex에게 먼저 물어볼 수 있어야 한다.

예를 들면 다음과 같다.

```text
이 일을 하려면 네가 무엇을 알아야 해?
보통 이런 자료는 어떤 기준으로 검토해?
내가 놓치기 쉬운 조건이 뭐야?
먼저 작업계획을 세워보고, 내가 확인한 뒤 진행하자.
```

좋은 활용은 한 번의 완성형 지시로 끝나지 않는다. 대화가 쌓이면서 Codex가 사용자의 업무 맥락을 이해하고, 사용자는 결과를 보며 조건을 보완한다. 따라서 각 장의 예시 문장은 그대로 외우는 문장이 아니라, 대화를 시작하고 조정하는 방법으로 읽는다.

## 3. 각 장의 표준 구성

각 장은 같은 흐름으로 쓴다. 직원이 앞 장을 다 잊어도 이 구조만 보고 다시 진행할 수 있어야 한다.

1. 이 장에서 만들 결과물
2. 왜 이 작업이 필요한가
3. 준비물
4. AI에게 먼저 물어보기
5. 조건과 기준을 같이 정하기
6. 작업 맡기기
7. 막혔을 때 점검할 것
8. 결과물 검수하기
9. 혼자 해보는 과제
10. 오늘 배운 절차 정리
11. 다음에도 하게 만들기: Skill 메모

`실패와 검수`는 별도 장으로 두지 않는다. AI 활용에서 검수는 마지막에 한 번 배우는 단원이 아니라 모든 장에 들어가야 하는 습관이다. 각 장마다 "무엇을 믿으면 안 되는가", "어떤 근거를 다시 확인해야 하는가", "어떤 산출물이 나오면 통과인가"를 같이 둔다.

## 5. 차시별 프로젝트 설계

### 00. Codex Desktop 소개와 설치

- 목표: Windows PC에서 Codex Desktop을 설치하고, ChatGPT 계정으로 로그인한 뒤, 공개자료 실습 폴더를 만든다.
- 프로젝트: `codex-public-practice` 폴더를 만들고 Codex에게 폴더 구조와 샘플 파일 하나만 확인하게 한다.
- 제출물: 설치 확인 캡처, 로그인 확인 캡처, 실습 폴더 구조.
- 강조점: 실제 업무폴더 사용 금지, 공개자료/비식별 샘플/가짜 데이터만 사용, CLI는 뒤쪽 선택 과정으로 분리.

### 01. AI에게 일 맡기기

- 목표: AI를 단순 답변자가 아니라 작업자로 이해한다.
- 프로젝트: 여행 또는 출장 일정을 바로 생성하지 않고, 지도/후기/예약/트렌드 자료를 조사한 뒤 일정표를 만든다.
- 제출물: 후보 조사표, 일정표 HTML 또는 Markdown.
- 이유: 처음부터 행정업무로 들어가면 부담이 크므로, 개인비서 감각을 먼저 만든다.
- 검수 기준: 근거 링크가 있는가, 최근 자료인가, 광고성/부정확한 자료를 제외했는가, 일정이 실제 이동 가능한가.

### 02. 공개자료 폴더 읽히기

- 목표: Codex에는 실제 업무폴더가 아니라 공개자료, 비식별 샘플, 가짜 데이터만 맡겨야 함을 익힌다.
- 프로젝트: 공개자료 샘플 폴더의 파일명, 확장자, 수정일, 용도를 표로 정리한다.
- 제출물: 파일 인벤토리 표.
- 검수 기준: 공개자료만 사용, 원본 삭제 금지, 경로 표시, 파일 용도 추정과 사실 구분.

### 03. 문서 정리하기

- 목표: AI에게 명단을 정리하게 하되, 정렬 기준을 함께 확인하는 법을 익힌다.
- 프로젝트: 교육대상자 명단을 부서 직제순으로 정리한다.
- 제출물: 직제순 정리 CSV, 부서별 Markdown 표, 정리기준 확인메모.
- 배울 점: 직제순은 AI가 알아서 맞히면 안 된다. 부서 순서 기준표를 주고, 기준표에 없는 부서는 확인필요로 남겨야 한다.

### 04. Browser Use: 웹브라우저 조사와 자동화

- 목표: Browser Use가 단순 검색이 아니라 웹 화면을 같이 보며 처리하는 방식임을 이해한다.
- 프로젝트: 예약 취소 경로 확인, 멤버십 해지 방법 확인, 서버 설정 보조 같은 시연 사례를 보고, 실습은 공개 웹사이트 조사로 진행한다.
- 제출물: 작업 체크리스트, 근거 링크표, 캡처 폴더, `results.csv`.
- 배울 점: 한 번 보고 판단할 일은 Browser Use로 충분하고, 여러 번 반복할 일은 Playwright로 자동화한다.
- 안전 기준: 내부 시스템 계정, 행정망, 개인정보 포함 화면은 사용하지 않는다. 예약 취소, 결제, 서버 삭제, 권한 변경 같은 최종 버튼은 사람이 직접 판단하고 누른다.

### 05. HTML 보고서 만들기

- 목표: AI가 만든 결과를 브라우저에서 보기 좋은 업무 공유물로 조립한다.
- 프로젝트: 조사 결과, 표, 캡처 이미지를 하나의 HTML 보고서로 만든다.
- 제출물: HTML 보고서.
- 검수 기준: 제목, 요약, 표, 근거, 캡처, 확인일이 있어야 한다.

### 06. 공개 Skill 찾아 사용하기

- 목표: skills.sh나 GitHub에서 마음에 드는 Skill URL을 복사해 Codex에게 "이거 써볼래?"라고 묻는 가장 쉬운 사용 흐름을 익힌다.
- 프로젝트: YouTube downloader Skill 페이지 URL을 Codex에게 주고, Codex가 용도와 사용 방법을 설명한 뒤 테스트로 실행한다.
- 제출물: `skill_사용메모.md`, `youtube_downloader_실습기록.md`.
- 강조점: 사용자가 설치 명령을 외우거나 GitHub 코드를 먼저 읽을 필요는 없다. URL을 주고 Codex가 설명하고 진행하게 한다. 다만 최종 설치와 실행 전에는 위험한 동작이 없는지만 확인한다.

### 07. Skill로 남기기

- 목표: 한 번 성공한 작업을 다음에도 반복할 수 있게 절차화한다.
- 프로젝트: 앞 장에서 완성한 작업을 `SKILL.md` 초안으로 정리한다.
- 제출물: 내 업무 Skill 초안.
- 대화 시작문:

```text
방금 우리가 완성한 작업을 다음에도 반복할 수 있게 정리하고 싶어.
네가 Skill 초안을 만들려면 무엇을 더 알아야 해?
먼저 발동 조건, 입력자료, 처리 순서, 검수 기준을 질문 목록으로 만들어줘.
```

### 08. 기존 PPTX를 읽혀 `design.md` 만들고 새 PPTX 생성하기

- 목표: 기존 교육 PPTX를 단순히 복사하지 않고, 스타일 규칙으로 추출한 뒤 새 자료에 적용하는 방법을 익힌다.
- 프로젝트: 기존 교육 PPTX 또는 공개 샘플 PPTX를 Codex가 분석하게 하고, 색상/폰트/레이아웃/문장 규칙을 `design.md`로 정리한 뒤 짧은 PPTX를 새로 만든다.
- 제출물: `design.md`, 샘플 PPTX, 검수 메모.
- 배울 점: "서식 참고"는 감으로 비슷하게 만드는 일이 아니라, 표지/도비라/본문 레이아웃, 색상, 폰트, 여백, 한국어 줄바꿈 규칙을 문서화하는 일이다.
- 검수 기준: 폰트가 의도대로 적용됐는가, 같은 어절 안에서 줄바꿈이 생기지 않았는가, 하단 여백이 과하지 않은가, 기존 PPTX의 톤은 살리되 민감한 내용이나 저작권 표시는 제거했는가.

### 09. `/goal`로 메모장 클론 프로젝트 끝까지 밀고 가기

- 목표: 한 번의 질문으로 끝나지 않는 작업을 목표 단위로 맡기고, 구현/빌드/검증/수정까지 이어가는 흐름을 익힌다.
- 프로젝트: Windows 기본 메모장을 참고해 작은 메모장 클론을 만든다. 최소 범위는 새 파일, 열기, 저장, 다른 이름 저장, 찾기, 글자 크기 조정이다.
- 제출물: 실행파일, 간단한 사용설명, 검증로그, 회고.
- 배울 점: 코딩 지식 자체보다 중요한 것은 목표를 잡고, 범위를 줄이고, 결과물을 실행해 보고, 수정 요청을 이어가는 방식이다.
- 검수 기준: 실제로 실행되는가, 파일 저장/열기가 되는가, 오류 상황을 처리하는가, 설치파일 또는 실행파일 위치가 정리되어 있는가.

### 10. Codex로 서버/API 설정 관리하기

- 목표: 사용자가 완성형 프롬프트를 쓰지 않아도, 짧은 말에서 시작해 Codex가 질문하고 사용자가 고르며 API 분석 범위를 맞추는 법을 익힌다.
- 프로젝트: Meta 공식 문서와 개발자센터를 확인해 Instagram/Threads 분석 가능 범위를 나누고, 가능하면 Browser Use나 Playwright로 화면을 보며 테스트 세팅을 진행한다.
- 위치: 04장 Browser Use/Playwright와 같은 맥락의 작업이지만, 입문 단계에서 바로 하기에는 어려워 별도 심화 장으로 분리한다.
- 제출물: `meta_api_가능여부.md`, `.env.example`, `api_test_log.md`, `instagram_threads_분석.html`, `다음번_세팅메모.md`.
- 배울 점: API 설정은 목적이 아니라 반응 추이 분석을 위한 준비 과정이다. 사용자는 "어떤 지표를 볼 수 있는지 네가 설명해줘, 내가 골라볼게"처럼 말하고, Codex가 가능 여부·필요 권한·테스트 방법을 확인하게 한다.
- 안전 기준: 기관 공식 계정, 운영 앱, 액세스 토큰, 앱 시크릿은 실습 문서와 캡처에 남기지 않는다. 실제 권한 신청, 운영 전환, 결제, 삭제는 사용자가 직접 판단한다.

### 99. 최종 프로젝트

- 목표: 각자 매달 또는 매주 반복하는 업무 하나를 Codex로 해결한다.
- 프로젝트 후보:
  - 교육대상자 명단 직제순 정리
  - 보조금 정산 검토
  - 공모전/정책공고 스크리닝
  - 부서 제출자료 취합
  - 법령 근거 검색
  - 회의록 정리 후 할 일 추출
  - 행사 홍보자료 HTML/카드뉴스 원고 만들기
  - 기존 PPTX 스타일을 참고한 교육자료 초안 만들기
  - 공개 API 설정 체크리스트와 데이터 분석 보고서 만들기
- 제출물: 최종 결과물, 작업 회고, `SKILL.md` 초안.

## 6. 교재 문체 원칙

직원용 교재는 개발자 문서처럼 쓰지 않는다. 다음 원칙을 따른다.

- "터미널", "스크립트", "MCP" 같은 용어는 필요할 때만 쓰고 바로 업무 언어로 번역한다.
- 모든 장은 결과물부터 보여준다.
- 예시 문장은 복사해서 붙여넣는 정답 프롬프트가 아니라 대화를 시작하는 말로 쓴다.
- 목적, 입력, 산출물, 검수기준은 사용자가 처음부터 다 쓰는 것이 아니라 Codex에게 물어보며 같이 정하게 한다.
- 긴 예시가 필요할 때도 "완성형 프롬프트"처럼 보이지 않게, 첫 말과 후속 질문을 나눠서 보여준다.
- 실패 사례를 숨기지 않는다. 오히려 "왜 틀렸는지"가 교재의 핵심이다.
- 마지막에는 항상 "이걸 다음에도 하려면 무엇을 남겨야 하는가"로 끝낸다.
